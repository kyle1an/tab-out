# Title Expansion Measurement Stays Per-Surface

Page Chips and Activation History rows measure their hover expansions with their own engines built on the shared title-expansion primitives (measure element, width search, line capture). A shared `createTitleExpansionMeasurer(config)` was designed (plans/008) and rejected during implementation (2026-07-13): the two engines differ on nearly every policy axis — Page Chip has title-variant early paths, hydrating-pill natural widths, constrained packed-width fallbacks, and a marker-wrap fits check, while history rows have their own fixed-line overflow predicate, line-height source, and expanded-layout cache — so the unified config would have been as wide as the code it hid. The deletion test fails: removing either engine would not re-materialize the other. The primitives exported from `src/components/title-expansion/index.ts` are the sanctioned seam; measurement policy stays with each surface. Do not re-suggest converging the engines unless the surfaces' measurement policies themselves converge first.
